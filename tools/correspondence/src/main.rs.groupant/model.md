## model

# Correspondence CLI model

## forward
Accept exactly scan REPO REGISTRY CATALOG NEW_JSON. Run corpus::scan first; serialize a successful report with serde_json pretty formatting, then mova_modelcheck::write_new using create_new and sync_all. Print output path, coverage and explicit non-proof/non-substitution fields. Invalid arguments, scanner failures and existing output paths return errors.

## behavior-complement
Within stable input files and successful allocation, excluded behavior includes accepting a different command/argument count, overwriting an existing report, presenting a scanner failure as success or marking a finite report as proof. The CLI does not run teacher calls, training, production replacements or network requests.

## reverse-reconstruction
A successful report and console summary admit every invocation naming the same readable inputs and a previously absent writable output path. Serialization is a projection and cannot uniquely recover the shell environment, filesystem history or executable context. An existing-file error does not imply invalid formula semantics. If a write/sync fails after create_new, a partial file may remain; no atomic-replacement guarantee is claimed.

## invariant
No output file is created until the scanner returns success. create_new protects existing output bytes. The scanner owns ownership/hash/type validation; CLI composition preserves the scanner report and adds only a concise status line.

## cost
Scanner cost plus O(J) JSON serialization/write bytes for report size J; sync latency is environment-dependent. Arguments and report output are not semantically interpreted by the CLI.
