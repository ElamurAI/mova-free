# Feedback and lexical projection

## forward

First project review questions to phase=exercise and require equal length and pairwise question/answer identity with lesson exercises. Deterministically shuffled answers produce feedback F without changing retained fingerprint; priorities(P,F) then creates one lexical row per packet word.

## behavior-complement

A successful feedback result with assessment-only questions, changed question/answer identities or changed retained fingerprint is outside the guarded relation. The fingerprint observation is narrower than proof of all possible hidden state preservation.

## reverse-reconstruction

Given F and priorities, reconstruct compatible exercise subsequences with identical source/question/expected and compatible answer observations, plus arbitrary omitted assessment rows subject to external validation. Correct/understood/support flags do not uniquely identify retained parameters.

## coupling

Feedback order supplies indices; priority child aggregates weak flags but ignores understood. The projection therefore loses assessment rows and fine answer evidence. Preserve all compatible inputs in the converse instead of inferring that absent support proves absent knowledge.

## composition

The child consumes F only after question alignment and fingerprint checks. No learner update is authorized in this fragment. Feedback cost is two fingerprints plus one answer call per exercise; add child aggregation once. Existing identity/tamper tests cover guards; no full retained-state semantic equivalence is claimed.

## invariant

Forward and reverse observations refer to the same fixed source snapshot and dependency behavior. Ordering is deterministic for fixed inputs; filesystem/environment stability is assumed where relevant. The complement is an inner bound relative to this fragment's input/output universe.

## checks

See the file-level ../model.md#tests for executed bounded checks and limits. The first three model relations are specifications; tests sample correspondence rather than proving all inputs. No expanded semantic AST or executable general inverse solver exists.
