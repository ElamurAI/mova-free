# eel-native-learning

## model

# Public native Eel composition

## Descriptant

Public controller, actual Mova native parser trainer and typed receipt interpreter.
A private or third-party TrainingData implementation supplies versioned annotation
snapshots and optional reviewed-priority authority. It cannot substitute raw AI
responses for admitted training labels. Source migration and active runtime remain
separate, as do protected metadata exclusion and assessment of protected labels.

## Forward

At a safe slice boundary, controller checks recovery/cooldown/storage/idle driver
observation, releases probe lease and enters trainer. Trainer selects admitted
priority data ahead of ordinary DB status/export; pending review excludes ordinary
training. It acquires its own inherited shared GPU lease, freezes actual agreement,
backs up compatible model, invokes native baseline/train/reload and developer/anchor
gates, conditionally installs and writes terminal receipt. Priority terminal ack,
Eel summary and counter/cooldown follow as distinct durable operations. Typed
interpretation E classifies the declared outcome and actual lineage separately.

## Invariant

No teacher or external AI request originates in this composition. No busy/unknown
idle probe submits a new round. No uncertain reservation automatically repeats
compute. Priority data uses the same protected/development/gate checks, not a
shortcut. Actual-parent and proposed-parent observations remain distinct. Deferred
rounds can advance counters and retain rejection streaks without learning.

## Cost

Compose filesystem/data/model scans, bounded driver queries and native parser
training; backup/install costs O(model bytes). Queues, concurrent disk writers,
GPU teardown and backend callbacks can add latency. No instantaneous preemption,
throughput/fairness proof or measured speed gain is claimed.

## Composition

TrainingData -> source-bound export -> native agreement -> gparse -> checked install
-> trainer receipt -> optional priority ack -> Eel summary -> evidence projection.
Pure receipt classification preserves outcome-specific evidence categories but
loses metrics/artifact existence. No atomic transaction spans DB/model/queue/summary.
Public crate and private adapter compile without a public dependency on private
modules; runtime adoption must verify the selected immutable executable.

## behavior_complement

Domain: cooperative native continuation with backend-authorized reviewed exports.
Observation: ordinary calls, native commands and terminal summaries. Assumptions:
correct pinned backend/paths, shared lease cooperation and defined local policy.
Relation: pending admitted urgent review excludes ordinary training; deferred/threshold
outcomes exclude recorded new learning. Counterexample: a counter advanced after a
lease race while no actual-parent/candidate/generation existed. Evidence: finite
public entrypoint, priority exclusion and evidence controls. Not a full proof.

## reverse_reconstruction

Domain: trainer/Eel terminal evidence. Observation: outcome plus actual hash tuple.
Assumptions: local declared receipt semantics. Relation: installed reconstructs a
claimed parent/output-generation tuple; rejected a parent/candidate tuple; deferred
retains many compatible no-training paths. Counterexample: proposed-parent alone
does not identify actual leased parent. Evidence: finite lineage and alias tests;
pruned artifacts/hidden optimizer state cannot be uniquely recovered.

## admission_install_ack_partition

Domain: priority review admission, native installation and durable queue ack.
Observation: priority state, native receipt and acknowledgement Result. Assumptions:
backend implements idempotent durable ack and cross-round deduplication. Relation:
review_only excludes ready export; native installation does not imply ack success;
ack failure preserves terminal native receipt and excludes compute replay in the
same run. Counterexample: crash after install/before queue ack leaves new weights
and pending queue state; neither rollback nor automatic replay is justified.
Evidence: explicit post-install ack-failure Rust control. Across-system recovery
requires reconciliation; no multi-file transaction or live deployment claim.

## tests

### Finite checks

Fourteen inherited controls cover native command protocol, real file descriptor
inheritance, agreement/data filters, rejection/resource partitions, thresholds,
compatible weight install and no uncertain replay. Added controls exercise full
public Eel/native callpath, distinct poll/export identities, malformed poll-path
exclusion, reviewed-priority precedence, unreviewed-priority exclusion and terminal
ack failure without compute replay. Together with Eel/evidence tests:29 identities.
Synthetic fake-executable checks are not real GPU-learning/generalization evidence.
