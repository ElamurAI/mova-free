# school-support

## forward
Tagged composition of the owned child mechanisms through shared identities and explicitly named external dependencies. Ownership is not a pipeline. The catalog records actual call edges and each unexecuted boundary.

## invariant
Use one compatible input/state/version at every actual join. Preserve parsed lesson/option identities and original indices for school selection. Keep supplied tree identity, label namespaces and candidate provenance for the separate reading and rule branches. Scope each invariant to its tagged entry point.

## cost
Lesson parsing and option scanning are linear in supplied text plus allocations. Benchmark selection sorts each stratum, O(N log N) total worst case. Tree-reading includes external parsing and many clause scans; pragmatic candidate enumeration can be cubic in atom count per site and rechecks at most 60 candidates per iteration. Do not sum mutually exclusive entry points or infer school score/latency.

## composition
schoolbench selection consumes knowledge::Lesson; schooltools and knowledge independently interpret shared lesson lines. school_tree builds school::Reading using frames parsing. prules consumes pragmatic reads/gold and persisted rejected-rule state. No direct school_tree/prules edge was found, so the group is a tagged support family.

## checks
Native parent checks live in world/tests/groupant_wave9.rs: school fixtures cover canonical options and stratified selection. Other parent catalog views are source inspection only; child fixtures provide their own narrower evidence. The integrated manifest binds final child revisions.

These peer changes were inspected, not executed by this harness. The integrated manifest binds the final child source bytes; native parent joins and child fixtures retain separate evidence scopes.
