## core-model

# Knowledge-memory interaction model

Registered children: placement-metadata, global-catalog and hot-state. Their source closure is bound by the parent manifest. Model ownership is a tree; actual calls can cross that tree.

## Forward

The modeled relation is a tagged union R = R_meta + R_catalog + R_local. Metadata recommendations, compiled catalog queries and local hot-state helpers have separate inputs and observations. There is no automatic join from one branch's successful result to another branch's storage, activation or learning operation.

Metadata: (c,e) -> (F(c),e), with opaque external state e untouched. F(c)=(1,i,(s!=Instance) AND m AND r AND NOT t,t). Durable recommendation is true; eligibility equals importance; alternatives equal conflict; proposal implies a reviewed non-instance foundation without conflict. Storage state is not an output of F.

Catalog: APIs observe compiled concepts, links, expressions and judgments. Generated tables and their seed provenance are not fully bound by the registered source hashes. Lookup success does not establish all-human knowledge coverage or persistent admission of a new fact.

Local state: the bounded model covers line-delta generation/application and checked parent traversal, with source-level caller wiring into materialisation, story and branch selection. A generated delta reconstructs its target line vector under the child domain. Ancestry validation checks only the selected path. File publication, concurrent writers, complete checkpoint integrity and other state-module operations remain outside the executable evidence.

## Composition and invariant

For each operation, preserve its tag, line sequence, parent-map snapshot and missing-link policy. Reconstructing equal lines does not recover unique deltas or ancestry, and does not prove equal knowledge semantics. Child source identities bind an epoch; they are not proof that runtime files are authentic or unchanged.

Intended global wiring remains: admitted record -> durable provenance record; usefulness -> budget-constrained activation; reviewed mechanisms -> versioned promotion. The local hot-state module is an existing artifact mechanism, not this complete global-store protocol. No transaction protocol or automatic skeleton generator is established by these checks.

## Cost

Streaming n metadata recommendations costs O(n) time and O(1) auxiliary space. Catalog costs depend on the queried operation and fixed tables. Local diff uses O(nm) time and space for line counts n,m, subject to line-comparison cost; application consumes a bounded source cursor and emits copied/inserted lines. Checked ancestry follows reachable links with ordered-set/map lookup costs. Count these paths only when executed; no training, GPU or throughput gain is measured here.
