# crab-orchestration

## descriptant

### Public Crab descriptant

Reusable worker code is public; concrete queues, runtime configurations and specialized research/training implementations stay in their deployment. Existing legacy IDs are preserved as technical identities. Steady-state autonomy and durable review checkpoints coexist with separate semantic/training admission gates.

A correct artifact digest alone does not validate the caller's identity/outcome labels. The native collector additionally compares decoded fields; external review labels remain declared evidence. This boundary is preserved in parent composition rather than hidden by a generic success count. Native graph retention is episode knowledge, not proof of general task execution.

## model

# Public Crab composition

## forward

An independent configured Crab process composes bounded request journals, append-only annotation versions, disjoint worker reservations and durable terminal review envelopes. Let C be the public controller, H an explicitly installed deployment handler, and G the ordinary protocol/pin/journal gates. For specialized operations, C_H(x)=H(x) only after G(x); C_None(x)=error. Existing wire names are compatibility identifiers, not public private-role implementations.

## behavior_complement

Domain: trusted local deployment/configuration and declared operations. Observe hook reachability, artifact identity and admission states. Assuming trusted embedding and Cargo integrity, C_None excludes specialized effects. Review publication excludes automatic learning admission. This is a scoped exclusion; an installed handler may fail or perform external effects.

## reverse_reconstruction

A durable artifact y constrains request/task/source hashes and declared state. R(y) retains all compatible worker executions and semantic results. Equal status can arise from several hidden process histories; no unique inverse or scientific correctness follows.

## invariant

Public dependency closure contains no private runtime source. Stable identities, unresolved reservations and source pins survive source relocation. Autonomous ordinary execution follows configured policy; semantic/training/code-application decisions are explicit checkpoints. Octopus develops, tunes, assigns and reviews logs, rather than serving as a synchronous per-action runtime dependency.

## cost

Compose source-hash/protocol/SQLite/terminal costs; downstream model/process latency is separate. No numerical approximation, speedup, full liveness or exactly-once theorem is claimed.

## composition

Public Fish annotation remains under annotation-orchestration; this group owns real generic control/storage/supervision/Dolphin modules and complete terminal Fish sources. Private Peta imports the public core and installs specialized handlers. Crab directly calls the public tools/agent-mova capability library for source-bound report collection and pinned read-only recall. The role-neutral agent-runner owns immutable queues, independent watch passes and no-replay reservations; concrete Fish own the AST/pragmatics preparation contract. Actual invocation, structural binding and semantic admission remain separate observations. The public `mova-terminal` group (tools/terminal) gives each animal that needs an LLM its own private terminal, held by a crab-tmux-worker that Crab starts; it asks one bounded question at a time and never uses a Dolphin.

## evidence

Offline scoped Rust fixtures plus public/fresh-local groupant and export boundary checks. Actual runtime cutover, terminal adapter certification, semantic review and learning-quality evidence remain separate.

## artifact_declaration_consistency

Domain: the native-report branch of bounded agent-mova collection. Observation:
accepted envelope fields and referenced report bytes. Let b be the bytes, h the
expected digest, r = decode(b), and let pi select schema, id, actor, capability,
outcome, source window and findings. The native admission relation is

    A_native(b,e,h) = bounded_regular(b) and H(b)=h and decode(b)=r
                       and pi(r)=pi(e).

The envelope's kind supplies the capability coordinate and its schema coordinate
is one. This is a source-derived admission model, not a mathematical proof of
SHA-256 injectivity, authorship, truthful claims or execution of the claimed task.
Trusted expected digests, cooperative ancestor directories and the configured
artifact format are assumptions. No compatible execution history is uniquely
reconstructed by acceptance.

Counterexample to a cheaper candidate: fix valid bytes reporting id B and outcome
uncertain, retain their correct digest, then declare id A or outcome supported in
the envelope. Hash equality remains true while declaration consistency is false.
The implemented native branch excludes both mismatches. External-review artifacts
follow a separate relation: their labels remain caller-declared review metadata,
with no native schema or semantic certification inferred from collection.

Evidence: the focused Rust test
collection_preserves_declared_failures_and_rejects_hash_or_identity_substitution
checks matching native admission, unchanged-byte identity/outcome substitutions,
invalid hash refusal and retention of failed/uncertain declared reviews. Evidence
is finite; no Lean theorem or universal semantic checker is supplied. Composing
control, native grouping and a durable review queue must preserve these format
and admission distinctions. Grouping labels is not learning a classifier.

## Evidence-preserving summary composition

Native collection groups on kind, declared outcome and evidence-binding category.
A checked native-field binding and a declared-only review therefore remain in
separate groups even with identical kind/outcome labels. Older unmarked summaries
retain a legacy-unclassified category when decoded. Child identity admission
alone did not establish this parent property: the former two-key grouping lost
that distinction. The mixed-evidence Rust counterexample exercises the repaired
composition. Counts retain their scope as metadata counts, not independent
witnesses or semantic approvals. Parent identity formulas are source-derived;
id/outcome have an exhaustive conditioned four-case check, schema/source/findings
have bridge controls, and actor/capability equality is source-inspected.

## sampled_health_observation

Domain: successful watch passes over an immutable ordered queue under the runner lease. Let H(r) be the serialization of all Summary fields except attempted_this_pass; its ordered job projection retains id, state, native_outcome and detail. Emission occurs on initial observation, attempted activity or H(r) differing from the last emitted signature. The first observed STOP changes that signature and is emitted before exit. Unchanged idle polls, including activity-count decay alone, do not emit. Changed observations never authorize replay or repair.

Counterexample: after a cached completed job is observed, changed bound report bytes produce integrity_failure with zero attempted jobs. The previous activity-only emission rule lost that transition. A focused test uses fabricated cached receipt metadata and actual Runner::pass under allow_trace=false; it never executes the missing pinned recall. It checks degradation, unchanged polls, restored bytes and restart snapshot. Separate synthetic-summary controls cover outcome/detail/admission/STOP and activity changes. These are finite software checks, not execution attestation for fabricated receipts. Queue/lease/reservation library code is unchanged.

The converse of a log line retains several compatible causes: initialization, activity, a sampled signature change or STOP. Silence excludes emitted qualifying transitions at sampled successful passes, not changes between polls or watcher downtime. Assumptions include successful polling, serialization and output writes on a trusted local filesystem. Stdout is flushed but not a durable transaction log. Lease-free status remains nontransactional and may transiently see a directory before its reservation is published. Parent collection must preserve failed/uncertain evidence independently of whether an observation line was emitted. See [the worker review](../../docs/animals.md).

## Native capability and priority composition

Domain: bounded ordinary English prompts, a pinned native syntax model, installed capability handlers, cooperative local files/sockets and separately admitted annotation exports. The deputy records actual UD and native question-frame observations. Its bounded skeleton resolves configured predicates/entities into capability IDs; unsupported scope, negation, missing reference or ambiguity can instead produce a review-only diagnostic. A supplied handler extends execution; initial adapters do not establish arbitrary task understanding. Trained pragmatic inference is explicitly absent in the current deputy.

Let N(p) be the observed native trace with either a plan or diagnostic d. Admission A(d,s) is a separately bound operator decision for stage s. Fish-ready requires A(d,annotation_ready); a raw diagnostic or consultant report does not imply it. Eel-ready additionally requires a reviewed immutable teaching export, independent parser witnesses, admissible record IDs and the existing protected-data/generation gates. These are distinct relations with explicit adapters, not one total self-training function. A priority receipt does not recover the unrecorded intended referent or prove a proposed annotation true.

The scheduler orders admitted urgent jobs at cooperative boundaries. PAUSE does not interrupt an in-flight child; ordinary quiescence must be observed by the deployment before urgent dispatch. Exact owned markers may be removed, foreign markers persist, and an uncertain reservation blocks automatic replay. Eel terminal diagnostic identity must equal the selected diagnostic before acknowledgement; an old ordinary receipt with the same generation is a counterexample to generation-only joining. Deferred/threshold outcomes do not establish GPU training. No fairness, uninterrupted liveness, generalization or whole-pipeline numerical error guarantee follows.

Finite evidence: native plaintext controls exercise configured paraphrases and refusals; generic Fish controls cover ordering/markers/uncertainty; Eel controls cover actual Rust callpaths with synthetic native executables, priority order and acknowledgement. These are different fixtures, not a single end-to-end learner assessment. An authored development prompt with an unresolved possessive supplies a useful negative case: refusal can be correct behavior rather than a parser defect requiring training. Source bindings and historical observations remain separate from proof.

## Read-only status observation join

Type: observation_projection. Domain: a fixed trusted attachment catalog, bounded regular status artifacts and the public status operation. For each attachment a with expected kind K and configuration digest H, read bounded bytes X at time t. Only when JSON(X).kind = K and JSON(X).config_sha256 = H does the observation expose the fixed scalar/counter projection P(JSON(X)); otherwise retain the missing/read/malformed/identity partition and no projected worker state. The artifact hash and read time bind the observed bytes, not their authorship or semantic truth. Freshness is a separate coordinate, including unknown and future timestamps.

Composition preserves a distinct read-only section: legacy role pause/resume/start does not gain authority over attached workers. A current matching artifact can coexist with a dead process; a stale or absent artifact can coexist with a running one. Its reverse fiber therefore retains both histories. Counts at preparation, source-target validation, batch-job review and training stages have different units and cannot be added into a learned-knowledge total. Separately read artifacts also do not form an atomic global snapshot.

Counterexamples: silently mapping a new worker onto an old failed role hides a real historical failure; accepting a kind/config mismatch aliases distinct campaigns; treating heartbeat freshness as health invents a stronger observation. Native module and integration controls cover these exclusions and preserve old controls. A direct read-only invocation against live status artifacts retains current source counters while an older status lacking identity fields remains an explicit gap. Finite evidence does not prove liveness, semantic correctness or training admission. Cooperative ancestor directories, trusted catalog configuration and ordinary descriptor IO remain assumptions.

#### Worker lifecycle interaction (2026-11-03)

Octopus sends Crab English prompts; Crab's native deputy maps configured capabilities (`crab_control`) to
worker_status/start/stop/restart, and Crab's worker supervisor (`workers.rs`) performs them in non-blocking ticks.
After a reboot, an external starter launches Crab; Crab adopts verified running workers and starts autostart
workers, GPU workers only after a passed `nvidia-smi`/probe check. The wiring is checked on fixtures (fake shell
workers, fake nvidia-smi, real native parser for the prompts); leaves being correct does not prove a live
deployment, which is a separate checkpoint. Crab does not yet message workers in English.

### 2026-11-04 · document

#### Work flow and council composition (2026-11-04)

crab-flow reads configured worker files and acts only through crab-workers (start, restart) and pause files;
crab-council consumes flow status/capacity/journal and the consult queue (crab-consult-queue) and executes a
unanimous allowed verdict back through flow's bounds. Interaction invariant: the only paths from an LLM
answer to an effect are (a) a typed verdict identical across every council member and admitted by
flow::council_decision, never a capacity verdict; (b) none from consult advice. Correct leaves do not prove
this wiring: the angel test flow_probes_act_journal_and_answer_through_dispatch covers flow -> workers ->
attention; the council -> flow execution path is covered only with a fake pod.

#### Epoch 2026-11-04 (work pools)

`crab-pool` joined under the flow: a pool leases one (job, part) unit to each idle member (a configured worker with an
assignment and a report file), renews a lease only for a running member with a fresh report, releases on finished,
stopped, refused or expiry, and journals each assignment and release. The interaction with `crab-flow`: Flow owns the
pools, ticks them after the probes, and shows them in flow_status, the council digest and the capacity review; a
stopped or refused member becomes an attention item. The member side is `mova-nautilus-pool`. Finite checks with a
fake supervisor; no live pool was run.
