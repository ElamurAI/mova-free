# translation-evaluation-pipeline

## forward

bible/sources supply VKey text maps; corpus groups and parses into PVerse. main evaluates target-population records with measure's reader/encoder/stack residuals and paired-source aggregates; blocks combines chapter-local layouts and reader scripts. many independently orchestrates multi-translation pair accounting from the same corpus/measure representation. report and pages consume residuals and normalized counts.

## invariant

Explicit valid tree/key/population domains; residual-assisted exact target reconstruction remains distinct from normal translation scores. Original production bytes preserved. Finite arithmetic and representable counters required; Docs sample n>0; storage membership indices<64.

## cost

Sum delegated parser/reader/training work plus O(P²) pair state/work per streamed block; retained training and optional dev metas prevent constant-space claim. LIS O(nlog n), UPGMA O(n³) distance visits, BTreeMap accounting O(tokens log vocabulary), rendering/output byte costs. Compact12C+17E+8T is conceptual bytes, not RAM.

## composition

Real joins: bible::read_pool/sources text→corpus PVerse; main run_sys→measure::Run→Agg/VRec→block_measure and report::write; many→corpus/measure plus own pair metrics; pages receives wlc_jps VRec stage arrays from main and Hebrew encoder outputs. many::agree skips punctuation while block_meta includes it: their counts are not interchangeable. Report groups collapse layers. No invented call from report to many.

## domain

Synthetic in-memory keys, residuals, metric records and permutations for executed evidence. Full CLI and real corpora/models/annotators/training/page/report effects are source-inspected only.

## limitations

Finite admitted numeric domains and valid trees; each task owns its files; no claim about empirical corpus quality, persistent learning, or full pipeline correctness.
