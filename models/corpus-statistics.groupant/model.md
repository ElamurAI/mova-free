### Corpus statistics descriptant

#### Current mechanism

This parent joins the shared `events::book_body` dependency with two distinct consumers and records poly as a separate extraction branch. The useful shared object is a selected raw body; downstream alphabetic histograms, parsed event tuples and detokenized story TSVs observe different units. The hierarchy is an ownership/model grouping, not a newly implemented processing pipeline.

#### Combiner inputs and output

Combine the authoritative source bindings and their partial syntax/model/evidence artifacts with model.md#core-model and the typed views. The original ten views retain their three-branch scope; three additional views extend selected-body gating, lexical mining feedback and tagged reconstruction. The first family entry specifies conditional excluded observations; the second retains compatible branch-tagged inputs, dependency state and ambiguous histories. Composition preserves the actual raw text, histogram totals, floating values and branch tag. The output of this modeling step is a source-inspected interaction specification and explicit remaining obligations, not an automatic reconstruction solver or a semantic correctness certificate.

#### Prospective joins and evidence boundary

The source model predicts that a public register file-reading run applies exactly the same body bytes as events::book_body for each readable snapshot, but this parent has not executed that full runtime/I/O join. Native child tests exercise pure body/count composition, numeric fixtures and role/token projections; they do not establish successful corpus publication or synchronized cross-branch snapshots. Potential future checks would use explicit immutable input files, compare body policies, and bind generated artifacts to input hashes. Those checks are proposed, not executed or authorized by this document.

No benchmark, approximate error budget, parser-quality improvement, teacher call, GPU result or universal proof is inferred from this parent.

#### Book observation and lexical feedback epoch

The hierarchy now also owns bookans and idioms. A real bounded join feeds the
selected events body directly to the book copy gate and distinguishes excluded
prefix/suffix text from selected story windows; quote rejection remains
independent. This adds correspondence for supplied immutable bytes without
claiming a full book/teacher pipeline or unique source-passage recovery.

Idiom mining's apparent literal-oddness signal already incorporates existing
idiom suppression. Preserve this feedback dependency and the process's
once-loaded global hot snapshot. Re-exporting candidate seeds does not imply
they became active, and same TSV inputs can classify differently under a
different loaded lexical snapshot. Older event/register/poly views remain
valuable within their three-tag scope; the new preimage view extends the
universe without overwriting those scoped observations.

# Corpus statistics typed interaction views

## nonbehavior

Type: behavior_complement.

In the universe of branch-tagged input/result/effect observations, the source-derived exclusion relation includes a register histogram increment caused solely by an unreadable input; acceptance of a NaN register z by `z >= zmin`; event extraction being implicitly substituted for alphabetic register counting; and poly acquiring the parser or writing its destination after its own marker-order validation has already failed. These are conditional inner descriptions of excluded behavior. They do not exclude untested filesystem failures or declare all three branches semantically equivalent. Evidence: inspected caller order, native register filtering and poly early-error sentinel fixture.

## compatible-sources

Type: reverse_reconstruction.

For register output retain every pair of ordered readable/failed input-instance lists whose actual body projections and lowercase histograms, f64 scores, thresholds and formatting produce that output. Word order, rejected characters, failed paths and excluded text are generally unrecoverable; arbitrary prefix edits are allowed only when they do not change the first-marker selection. For event summaries additionally retain annotation/repair outcomes and omitted postings/tails; for poly retain heading selections and whitespace-compatible selected lines. These are constraint-defined preimages, not an implemented inverse enumerator. If outputs from multiple calls are asserted to share one raw snapshot, intersect their preimages on that same text and dependency state. Dropping the operation tag gives the union of branch-compatible explanations, not unique provenance.

## marker-policy-separation

Type: policy_difference_relation.

The shared events/register body helper searches marker substrings anywhere: start is after the first following newline or defaults to zero; end is the first END occurrence or text length; a reversed end yields an empty body via max(start,end). Poly instead selects lines beginning with START/END, requires both, rejects reversed order before slicing, and selects an exact heading plus an optional later exact end heading. A reversed-marker input can therefore give an empty register contribution while poly returns Err. Prefix/heading/line-boundary edits are not generally invariant across these policies. Evidence: native event body slices and poly malformed/repeated-heading fixtures; a simultaneous file-reading comparison of both public APIs is unexecuted.

## token-identity-boundary

Type: representation_relation.

Register splits the selected body at every nonalphabetic scalar, admits original runs of UTF-8 byte length greater than one, then lowercases. Thus ASCII A is discarded, single-scalar é survives, İ expands to i plus combining dot, and co-op becomes two runs. Events instead uses its sentence filter and annotator tokens, then selected noun/verb lemmas and roles. Poly records detokenized sentence text and counts tokens containing any alphanumeric character. Neither equality of printed text nor equality of a word spelling identifies equal token units across these branches. Evidence: the register Unicode histogram and child token/event fixtures; general tokenizer/lemma correspondence remains open.

## occurrence-versus-semantics

Type: observation_projection.

Register H measures admitted surface-run multiplicity and ignores sentence order and dependency roles. Event C measures accepted predicate/role tuples; actor weight sums role occurrences, so one noun used as patient and recipient contributes twice, and a first rejected role match can mask a later admissible noun. Consequently equal H does not imply equal C, equal C does not recover H, and neither score/count measures semantic completeness or truth. Reconstruction must retain the relevant ordering and parser state when event output is observed. Evidence: native role-masking and repeated-role aggregation fixtures; no new corpus-level equivalence experiment.

## floating-count-boundary

Type: numeric_representation_relation.

Original u64 histogram counts ca/cb are retained for emitted row counts and the exact ca >= min gate. Separate copies are converted individually to f64 for scoring, while na+nb is added in u64 before conversion. Those floating paths can diverge above 2^53; they no longer feed a cast-back count gate. The inherited targeted witness uses singleton counts na=2^53+1 and nb=2^53+2: alpha=999.9999999999998, both computed complementary denominators=2.2737367544323206e-13 and z=0.0. A singleton therefore need not be excluded as inf-inf NaN; the familiar small singleton result requires its actual computed zero denominators. The witness constrains this case only, not every large count. Additional native cases at ca=2^53+1 and ca=2^53+3 preserve exact returned counts, admit min=ca and exclude min=ca+1. Compiled old-code witnesses fail because the former cast-back implementation rounded counts and misapplied minimum thresholds. The correction preserves raw integer counts and their gate while leaving the floating z formula and NaN policy unchanged; integer overflow remains excluded.

## selection-and-display

Type: lossy_encoding_relation.

Selection precedes formatting: source f64 z must compare >=zmin and the original u64 register count ca must meet min exactly. Rows order by descending total_cmp(z), then lexical word, not by count ties. TSV rounds z to two decimal places and rates to one, so different selected score values can print alike and displayed equality with a threshold cannot reconstruct the original comparison. With a nonempty multi-key register and an empty reference, admitted finite scores can coexist with a reference rate 0/0; finite z does not guarantee finite formatted rates. Child threshold/tie and large-count gate fixtures are finite evidence. Selected row count fields preserve the exact input u64 values; z and per-million rates still use floating arithmetic. Full TSV rendering, including large-count decimal output, remains source-inspected only.

## publication-gap

Type: effect_trace_relation.

Register skips unreadable/non-UTF-8 inputs, but its header reports attempted path counts; final create/write/flush errors propagate. Events skips failed book reads and can discard per-book publication errors while successful-instance totals advance; later final-output errors can follow earlier successful files. Poly rejects extraction errors before destination writes, but its later write is not atomic. Thus an Ok result is not a common certificate that all inputs were consumed, all outputs exist, or an all-or-nothing transaction occurred. Evidence: source-inspected I/O control flow and the bounded poly sentinel fixture only. Successful public file pipelines, injected late failures and concurrent writes are unexecuted here.

## input-instance-identity

Type: provenance_relation.

Duplicate readable register path instances contribute repeatedly to the histogram; event corpus document support likewise counts successful input instances, not unique filesystem identities. Equal event filename stems can collide on disk while still contributing separately to pooled counts. Poly headers carry the named raw path and selections but no content digest. Therefore equal labels, paths or event counts do not establish that two branches used the same bytes or that outputs form one synchronized corpus snapshot. Preserving shared-snapshot identity requires external provenance absent from these APIs. Evidence: source-inspected folds/publication naming; duplicate-path and collision I/O experiments remain unexecuted.

## branch-cost-composition

Type: resource_composition.

Each selected branch charges its own whole-input bytes and dependency work, as defined in model.md#core-model. The direct register-to-body call is one helper invocation inside counting, not an extra complete event pass. Conversely a separate poly preparation incurs another complete raw read and scan, even if its selected story is tiny. No fictitious sequential poly->events->register pipeline, shared tokenization cache or cancellation of repeated reads is inferred. Serial peak and concurrent sum-space accounting require the actual invocation schedule; none is implemented by this grouping. Evidence: source-level loops and data retention; timing, allocation peaks and throughput remain unmeasured.

## selected-body-gate

Type: selected_snapshot_gate_join.

For a supplied immutable raw string x, B=events::book_body(x) and
G=bookans::Gate::new(B) share exactly the selected body bytes. The gate stores
normalized seven-word window hashes and scans answer windows; its independent
quote rule rejects matched quote pairs of at least four words even without
book membership. No source-path provenance is created by this composition.

selected_book_body_is_the_copy_gate_input builds prefix/body/suffix text with
explicit markers, verifies body selection, and checks copied body prefixes of
length 0..10 against COPY_RUN=7. Excluded nine-word prefix/suffix strings pass
the copy test; a novel quoted phrase fails independently. This is a bounded
pure-helper join, not the full bookans::run/teacher/retry/log path. Hash collisions,
case/punctuation normalization and adjacent hashes from different source
positions prevent interpreting every flagged run as one uniquely located
verbatim passage. Gate acceptance is neither factuality nor legal certification.

## lexical-mining-feedback

Type: seed_feedback_boundary.

idioms::run consumes OBJ cell/event exports plus dictionary/MWE inputs, but
classification additionally consults Matrix::global().score(v,n,OBJ). That
score already uses existing global idiom/light-verb/collocation knowledge to
suppress literal OBJ oddness (clamping a known score to at most one). Therefore
the miner's literal_odd predicate is suppression-aware, not a raw independent
selectional-violation measurement. Earlier accepted lexicon can alter later
mining classification even when the supplied TSV bytes are unchanged.

Global hot overlays are loaded through OnceLock: the in-process first loaded
snapshot, environment/path selection and fixed seeds belong to the input
context. Writing a new idioms.tsv does not establish that an already loaded
process rereads it or that exported rows become active knowledge. Dictionary
evidence bypasses corpus min/min_books but still requires OBJ count>=3;
duplicate pair rows replace pair counts while total/marginals accumulate.
Particle exports can overwrite a matching final pair. These source-inspected
relations are not an executed feedback/training loop. Child finite tests cover
dictionary/MWE parsing and ordering, not full mining, output activation,
concurrent publication or a factual assessment of inferred idioms.

## core-model

# Corpus statistics interaction model

## Domain

Operation-tagged calls to corpus event statistics, register statistics, Gutenberg story preparation, book-answer gating/retrieval, or idiom mining. The input includes ordered path instances, readable UTF-8 contents or read failures, selected headings, options, and dependency state. Successful allocations and no integer overflow are assumed. Floating operations retain Rust f64 behavior, including rounding, infinity and NaN. Parser, dictionary, repair, tokenizer and filesystem behavior are conditional dependencies, not supplied by this parent.

Immediate ownership children include `corpus-events`, `corpus-register`, `world-poly`, `world-bookans` and `world-idioms`; final IDs/bindings are reconciled by integration. This hierarchy groups related observations, not an execution schedule. The original forward/cost paragraphs below describe the first three branches; the expansion section supplies the additional two.

## Forward

For register statistics, the inspected call edge is `register::run -> counts -> events::book_body -> count_body`; each readable path contributes its body to a lowercase histogram and total. `run` supplies two such maps/totals to `ranked_rows`, then formats selected rows as TSV. No event extraction, dependency parse or sentence splitting occurs in this branch.

For corpus events, `book_stats` reads a book, applies the same `events::book_body`, splits sentences with the event-specific policy, tokenizes/annotates/repairs, and accumulates ordered role events and sentence postings. `run` aggregates successful book instances and conditionally publishes per-book and corpus artifacts. Counts are observations of this extraction policy, not facts about all characters or actions in the story.

Poly is a separate branch: `prep` reads a complete raw file, calls `story_paragraphs`, acquires the annotator only after extraction succeeds, tokenizes/detokenizes paragraph sentences, then writes TSV. Neither register nor events calls poly. A user may separately pass a produced file elsewhere, but no such adapter or its semantics is modeled or executed here.

## Composition

Let B be `events::book_body`, H the alphabetic counting fold, and R the actual floating ranking/selection relation. On each readable register input instance x, counting uses H(B(x)); unreadable inputs contribute no delta. The two folds supply the same maps and totals to R and formatting. This equality of intermediates is the inspected cross-file join; it does not allow replacing H with event tokenization or B with poly heading selection.

The event branch also consumes B(x), but applies sentence filtering and dependency-based event projection. Its output is not an alternative implementation of H. The poly extraction relation P has a different marker/heading/error policy. Branch identity must remain in observations and reverse queries. Joint reconstruction must retain a shared raw text when two separately invoked branches are hypothesized to have read the same snapshot; independent child preimages cannot simply be multiplied. Concurrent read snapshots and a shared-output transaction are absent from the implementation.

## Invariant

Without u64 overflow, register histogram totals equal admitted alphabetic-token multiplicities before f64 projection. Empty/ASCII-singleton rejection happens before lowercase expansion. Event histograms count extraction occurrences, and repeated role occupants contribute repeatedly to actor/interactions summaries. These two multiplicity units cannot be equated.

Ranked register rows use descending `total_cmp(z)`, then word order for equal scores; NaN z never passes the source comparison. Selected row counts retain exact original u64 histogram values, and the minimum-count gate compares those integers directly. TSV integer fields format the retained counts without a floating round trip; scoring and per-million rates still undergo f64 conversion and can lose precision above 2^53. Poly early extraction errors precede parser acquisition and output writes. A successful event/register return does not establish that every attempted input was readable or every per-book artifact was published.

## Cost

Let N be total raw bytes read across the actually invoked path instances, K admitted register tokens, V union vocabulary, W_s annotated words in event sentence s, E event occurrences, D distinct event keys, L poly input lines, B selected poly bytes, T token characters and O output bytes. Register work includes O(N) byte scanning and O(K log(V+1)+V log(V+1)) map/sort operations, plus key-byte comparisons and output. Event extraction has the child's conservative O(sum_s W_s^3) scan bound plus counting/sorting O(E log(D+1)+D log(D+1)), raw/token/string bytes, and opaque annotation/repair costs. Poly whole-call work includes O(N+L+B+T+O), plus opaque annotation and I/O latency; excluded header bytes still belong to N.

For several separately invoked branches, add their actual work, including repeated reads of the same path: no shared read cache or unified controller exists here. Serial peak space is the maximum live branch footprint plus retained outputs; concurrent footprints may add. Poly retains the raw N-byte string alongside line references, selected paragraphs and output. Event worker/parser memory and filesystem latency remain unmeasured. These are symbolic bounds, not runtime measurements or speedup claims.

## Additional branch composition

Book-answer gating consumes normalized windows of the book bytes supplied to
Gate::new, and retrieval combines sentence-index occurrences with lexical hits
before top-30 selection, neighborhood expansion and source-order output.
The tested events::book_body -> Gate join binds one selected snapshot explicitly;
the parent does not assert that every book-answer entry point automatically
uses this adapter. Teacher responses, retries and print/log effects remain
separate conditional behavior.

Idiom mining reads cell/event/dictionary layers, applies ordered gates and
classification, then exports detailed rows and a final pair map. Classification
depends on existing global idiom suppression in Matrix::score. The first loaded
global hot overlay and fixed seeds are part of the state: output publication is
not activation or proof of a completed learning loop. Event/register token units
and mining counts remain distinct. Equal file paths do not establish equal
contents or an atomic multi-file snapshot.

For gate inputs of B normalized book bytes and A answer bytes, expected fixed-
window hashing/scanning work is O(B+A) plus output; collisions and allocations
remain implementation concerns. Retrieval sorts K candidates in O(K log K)
after index/sentence scanning. Mining over B input bytes, U unique pairs,
E event rows and R retained rows has conservative map/sort work
O(B+(U+E)log(U+E)+R log R), excluding key lengths and global lookup. Add costs
only for actually invoked branches, preserving repeated reads and once-loaded
initialization; no shared cache or throughput claim is implied.

Parent behavior complements and reverse reconstruction now include these two
tags as described in additional-branch-preimages. The first ten catalog views
continue to constrain their original three-branch observations. The six-test
integration harness has an initial debug pass reported by the integrator;
only its selected-body/gate fixture addresses this corpus subtree directly.
Final repeated profiles and compiled controls are integration evidence.
