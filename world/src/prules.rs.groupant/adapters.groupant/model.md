## forward

Clone reads and apply rules in order; dispatch CLI; rotate gold inside known splits; write queue/rules separately.

## invariant

Empty replay preserves base; shuffle preserves non-gold fields. Writes not transactional.

## cost

Replay O(lines*rules*apply cost); shuffle clones line and gold payload; external loads opaque.

## composition

Source-bound parent supplies exact shared state and dependency assumptions. Independently projected fragments do not prove their wiring.

## domain

Fix source revision, external dependency outputs, configuration and sufficient resources. Observe one terminating call or explicitly bounded trace. Arithmetic domains exclude overflow except named refusal tests. Specialized relations are source-derived partial models unless a finite oracle is explicitly named. No unrestricted reverse solver is implemented.

## behavior-complement

Empty rule replay cannot alter base reads. Shuffle cannot alter key/text/judged_only or rows outside dev/teacher. Successful control dispatch does not write the learn branch rules file. Sequential write failure does not imply rollback; these inner exclusions hold under fixed dependency behavior.


## reverse-reconstruction

Shuffle inverse rotates negatively within each known split and row ordering. Rendered F1 tables/example truncation admit many underlying counts and lines. Replayed frame output retains all base/rule sequences with the same ordered effect, including inert rules. Unknown ordering loses exact shuffle reconstruction.


## shuffle-inverse

For each dev/teacher split n>0, output[k].gold=input[(k+n/2+7) mod n]. Inverse is negative rotation; other row fields and other splits are identical. Empty split does no indexing. Original positions enable unique inverse permutation, duplicate values erase observable identity. Native sizes 0..16 check rotation, reconstruction and fields. No independence or useful statistical disruption guarantee.
