fn main(){
 let r=Path::new(env!("CARGO_MANIFEST_DIR"));
 let src=fs::read_to_string(r.join("../store.rs")).unwrap();
 let syn:Value=serde_json::from_str(&fs::read_to_string(r.join("syntax.json")).unwrap()).unwrap();
 let hash=syn["source"]["sha256"].as_str().unwrap();
 let defs=vec![
 ("lookup","identity","world-store-record-identity",vec!["same_stored_tree","decode","decode_tag","words","update"],
 "Resolve each stored lemma ID through the immutable parent lemma table. Compare token count and the sequence (UPOS, relation, head, tag, normalized lemma) against the new annotation.  "Valid enum bytes, representable heads and lemma IDs, canonical parent lemmas, fixed parent table and successful record reads. A true identity result preserves all stored semantic fields; it does not preserve omitted Word fields.",
 "Worst case O(T+B) for T tokens and B normalized lemma bytes inspected, versus the historical O(T) structural comparison. Short circuiting avoids later tokens; normalization allocates.  vec![

 ("representation-fiber","serialization_projection","Equivalent semantic records may use different numeric lemma IDs if their respective tables resolve to the same strings.  ("historical-loss","counterfactual","The historical (UPOS,relation,head)-only predicate merges distinct tag and lemma fibers. Rejecting a lemma-only or tag-only difference repairs this gate. It does not verify update annotation, read-error handling, publication ordering, same-hash early return or full codec capacity.")
 ]),
 ("lookup","lexical","world-store-lexical-projection",vec!["lemma_file","lemma_table_for","features","features_lex","index_full"],
 "Structural features count UPOS/relation and selected predicates/subjects with u8 saturation. Lexical features add subj:lemma only for Nsubj/NsubjPass and alphabetic lemma strings resolved from the version table. index_full rebuilds these observations from effective records, including inherited records.",
 "Inherited IDs must keep their parent meaning in the child lemma table. Valid dense unique canonical tables suffice; sparse/duplicate table construction and ID-width overflow remain separate risks.  "Per tree O(T+B) feature traversal plus ordered-map costs; full index rebuild visits all sentence IDs and materializes postings. Identity improvements do not eliminate rebuilding.",

  let nodes:Vec<_>=syn["nodes"].as_array().unwrap().iter().filter(|n|n["category"]=="item" && names.iter().any(|key|{

 }
