MMM v1 ("motivated steps"), deterministic Rust, no neural networks, never executes code.
Memory: 627 verified mlab programs (test scenarios of the language: suite-v1 204, suite-v2 36, 400 Opus scenarios -> 387), indexed by BM25 over our English lemmas of scenario titles plus identifiers in the code.
Pipeline for a task description (English):
1. UNDERSTAND: rule-based reading of the description: named literals ("v = [..]", "s = '..'", "n = 7"), ranges ("from A to B", "integers A to B", "first N positive integers", "below N", "a:b"), selection conditions (even, odd, divisible by K [or/and K2], prime, positive, negative, greater/less than K, at least/most K, perfect square), elementwise transforms (squares, cubes, square roots, absolute values, reciprocal, doubled), aggregates (count/how many, mean/average, median, product, sum/total, max, min), locate (index of max/min, first/last index satisfying a condition), sorting (ascending/descending), string ops on a given string (reverse, upper, lower, trim, replace 'a' with 'b', count a char, vowels, palindrome, length), digits of a number, recurrences (factorial, Fibonacci, gcd, lcm, Collatz), and the requested printf call (the name inside printf(..., name) becomes the result variable).
2. PLAN (means-ends analysis): each recognised item is a DIFFERENCE between state and goal (given, candidates, select, transform, order, aggregate, locate, represent, parts, repeat, present). Order: hard dependency tiers, ties broken by difference bigrams learned from 359 Opus-annotated math solutions. The move (operator) for each difference is chosen by an averaged perceptron trained on the annotated math steps (difference, previous move, question cues).
3. CARRY OUT, TWO PATHS: every move has a FAST realisation (a ready builtin: sum, numel, max, sort, find, fliplr, upper, strrep, factorial, gcd ...) and, where possible, a STEPWISE realisation without the ready tool (loops: accumulator, counter, running max, insertion sort, loop with break, char loop, Euclid loop). The submitted program is the fast path; every step carries a comment "Goal ... Motive ..." (motive = a code rule for the difference plus the medoid motive of the same difference->move cell in the math annotations, cited with its source id).
4. LOOK BACK: the stepwise path is an independent second way to the same result.
Fallback: if nothing beyond the given data is recognised, or a step lacks data, the program is the nearest memory program (v0 template: BM25 top-3, substitution of constants, first bracket literal, printf format, same-family builtin swaps; static scoring by parse success and coverage).
Known limits: one goal per task (multi-part tasks get only the first part); no user-defined functions (tasks asking for a function get a script); no tables, matrices, rewriting of given loops or C code; no recursion schema beyond factorial/Fibonacci/gcd/lcm/Collatz; memory examples are language tests, not task solutions.
